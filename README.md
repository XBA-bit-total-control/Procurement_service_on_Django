### Проект по _backend_-части сервиса для заказов _Compraretis_

Представляет собой REST API для работы с заказами на основе Django DRF

### О сервисе

Сервис для заказов _Compraretis_ предоставляет его пользователям и партнёрам широкий 
спектр взаимодействия через _API_.

Для тех, кто ещё не зарегистрировался, доступна удобная возможность поиска необходимых
товаров, магазинов и просмотр категорий.

Пользователи прошедшие регистрацию могут свободно добавлять товары в корзину, 
указывать контакты для доставки и оформлять заказы.

Для партнёров же предусмотрена возможность показа имеющихся товаров на продажу,
обновление и удаление информации о них. Также есть возможность отключить приём товаров.

### Внутренняя информация и условия работы

Предполагается, что пользователи имеющие статус _is_staff_ являются сотрудниками выполняющими
работу проверки и подтверждения создаваемых заказов, а также обработки обращений от пользователей.

Пользователи имеющие статус _is_superuser_ являются администраторами, которым доступен вход
и взаимодействие с админкой.

При ошибках связанных со взаимодействием с базой данных пользователю передаётся контакт одного активного
сотрудника или если активных сотрудников нет, то одного из всех имеющихся для решения вопроса
и проблемы, при обращении пользователя.

При неожиданных критических ошибках в работе сервиса в ответ пользователю отправляются
контакты одного из администраторов.

Поэтому для работы сервиса в базе данных необходимо создать как минимум одного пользователя
являющегося сотрудником и одного администратора, иначе при первом же возникновении ошибки
она не будет корректно обработана и вызовется другая информационная ошибка, а пользователь
не получит контактов для помощи.

### Запуск сервиса

#### __В контейнере__:

Данный проект докеризирован и поддерживает запуск в контейнере.

Для запуска нужно иметь установленный _docker_.

Из корня уже перенесённого проекта на устройство выполняется команда:
```bash
docker-compose up
```
Нужно дождаться старта всех контейнеров и после сервис будет доступен. 

Понять, что всё готово можно по строке в терминале содержащей:

```bash
service_compraretis-1  | Watching for file changes with StatReloader
```

Проект запускается в режиме отладки, а вся отправка email будет
происходить в терминал.

#### Прямой запуск:

Нужно иметь Python версии не ниже 3.13, а также PostgreSQL (рекомендуется 18 версия).

Во избежание проблем с библиотекой _ujson_ и с запуском приложения
_Celery_ настоятельно рекомендуется использовать _Linux_-подобные _OS_ для запуска.

Для разработки установка библиотек из _requirements-dev.txt_ предпочтительнее.

### Документация

Локальный хост для работы с _API_: http://127.0.0.1:8000/api/v1/

Все обращения к _API_ требующие передачи информации в теле запроса поддерживают
способы передачи данных/значение Content-Type: 
1) _application/json_
2) _form-data_
3) _x-www-form-urlencoded_

За исключением _PUT_-запроса на _user/contact_ - передачу в _form-data_ он не поддерживает.

Отдельной модели/таблицы для корзины пользователя не предусмотрено, в качестве неё 
выступает запись в таблице заказов со статусом _"NOT_CREATED"_.

Ограничения на количество запросов к _API_:
> Неавторизованным _10_/мин.
> 
> Авторизованным _20_/мин.

  "last_name": "опционально",
  "patronymic": "опционально",

Создаёт не подтверждённый профиль пользователя.

- __POST user/register/confirm - завершение регистрации пользователя__

  "email": "example@mail.com"

__Может принимать__: один товар в указанном выше виде, массив со словарями

Вернёт список всех заказов пользователя.

пользователя.

```json
{
  "url": "ссылка на yaml-файл c прайсом"
}
```
Обновляет или создаёт прайс партнёра/магазина.

ответ в виде отчёта о выполненных действиях.

Позволяет узнать статус запроса на обновление прайса.

Если задача завершена успешно или с ошибкой, то возвращается 
отчет о выполнении или информация об ошибке.

Задачи в другом статусе возвращают информацию о статусе.

### Партнёрам - работа с прайсом

##### _Инфо_:
Загрузка прайса на сервис происходит посредством считывания _yaml_-файла
из переданной ссылки в запросе.

С прайсом можно работать только применительно для своего магазина, а запрос 
должен отсылаться авторизованным партёром, прошедшим регистрацию.

Перед созданием такого файла рекомендуется ознакомиться с правилами по его оформлению
и готовыми примерами.

Любая ошибка при создании _yaml_-файла не позволит выгрузить прайс, в том числе и то,
что было оформлено верно. Партнёру при этом поступит информативный ответ об ошибке для исправления.

##### _Как оформлять_:

При составлении такого файла каждую категорию и товар нужно размещать 
как отдельный элемент списка для _category_ и _product_ соответственно.

Для добавления товара необходимыми полями к заполнению являются:
_category_, _name_, _price_ и _quantity_. 

Указать category можно её точным названием или идентификатором.

Поле _model_, если его не указывать, будет иметь значение _not_specified_.

Чтобы изменить имеющийся товар, нужно добавить указание его идентификатора.
При этом прошлая структура файла для создания товара должна сохраняться и меняться 
лишь те поля, которые необходимо изменить.

Чтобы удалить товар, нужно в значение поля _quantity_ передать _null_.
При этом для удаления товара обязательно нужно указать его идентификатор.

Изменение значения параметров происходит тем же образом - просто меняется 
значение в сравнении с начальным видом файла на создание.

Чтобы добавить новый параметр товару, нужно просто указать его название и значение.

Удаление параметра происходит аналогично удалению товара, только
вместо поля quantity используется значение самого параметра, в которое задаётся _null_.

##### _Примеры_:

Внутри проекта в директории _purchasing_service/backend/data_ находятся 2 _yaml_-файла
как пример для работы с прайсом.

Файл _example_of_new_products.yaml_ показывает примеры создания товаров и 
уточнят их вариативность.

Файл _example_of_changing_products.yaml_ показывает возможности правки информации
о товарах, а также их удаления.

Для использования на практике в запущенном проекте можно воспользоваться 
такими ссылками в запросе на обновление прайса:
1) Файл создания товаров - https://raw.githubusercontent.com/XBA-bit-total-control/Procurement_service_on_Django/main/purchasing_service/backend/data/example_of_new_products.yaml

2) Файл правки и удаления товаров - https://raw.githubusercontent.com/XBA-bit-total-control/Procurement_service_on_Django/main/purchasing_service/backend/data/example_of_changing_products.yaml

__Примечание__: во втором файле указаны идентификаторы товаров, предполагающие,
что товары были загружены из первого файла, а ранее из товаров или
категорий ни чего не было добавлено в базу данных.
